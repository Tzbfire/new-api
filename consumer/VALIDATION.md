## 实现范围

独立 `consumer/` 应用已实现落地页、模型与服务分组价格、流式聊天、本机会话、画室文生图/参考图/批量任务、持久作品库、API Key 创建/编辑/启停/查看/删除、统一 API 接入示例、使用量与调用记录、钱包充值/兑换码、套餐购买/扣费顺序/套餐历史、充值订单、个人资料与账户安全。

独立认证覆盖密码加密、Turnstile、MFA、Passkey、OAuth、邮箱绑定、恢复码、会话撤销及注销；没有把旧页面嵌入或复制到新项目。登录后回到白名单内的原目标页面。深浅主题、手机导航、七语言、加载/空/错误反馈已实现。

本次后端改动限于：`/api/pricing/quote`、`/api/user/topup/info` 兼容展示字段、OAuth 的 `callback_target=consumer` 和固定新回调、密码恢复可选新入口。没有修改数据库模型、迁移、现有查询语句、渠道调度、预扣/结算/退款实现。现有前端及管理路由保留。

工作区开始时存在 `web/default/`、`web/simple/` 未跟踪文件；过程中另一项认证维护产生并提交了其他改动。本任务没有替换、回滚或提交这些内容。

## 真实网关集成证据

集成脚本启动测试专用 Go 进程、随机密码与会话密钥、独立临时 SQLite 数据库，以及只监听 loopback 的合成上游。无继承生产 `.env`，无外部模型或支付服务请求。兑换码和套餐余额购买仅发生在本次生成的隔离测试数据库。普通测试退出时清理自己的临时目录与子进程；`--serve` 保留进程和数据用于体验。

- 数据库：SQLite **3.50.4**，来自二进制 `modernc.org/sqlite v1.40.1` 的嵌入版本元数据；不是对生产数据库版本的推断。
- `default=1×` 与 `premium=2×`，同一标准 token 情景返回 `$0.006` 与 `$0.012`。
- 完成 API Key 创建、显式查看、禁用、保留分组的编辑及删除；不打印密钥，不将其写入测试报告。
- 聊天经真实 `/pg/chat/completions` → 本地合成上游 → 流式页面，服务端扣费 **84 quota**。
- 图片预估两张 `$0.08`；后台真实批次产生两个 `SUCCESS` 任务，每张 **20,000 quota**；作品库展示并成功通过下载票据下载 ZIP。
- 日志扣费合计与钱包差额均为 **40,084 quota**（`$0.080168`）。这验证网关在合成上游响应下的实际本地结算，不证明真实供应商用量或实款到账。
- 验证支付功能关闭时的拒绝和空订单；开启隔离测试配置后兑换 **500,000 quota**，同一码重放被拒且不重复入账。
- 用这笔模拟余额购买一个测试套餐，钱包扣除 **500,000 quota**；验证限购、订阅状态和扣费顺序持久化，重复购买不再扣款。
- 套餐禁止钱包续费时，`wallet_only` 的调用返回 **403** 且无消费；切换 `subscription_first` 后聊天成功，从套餐单独扣除 **84 quota**，钱包不重复扣费。
- 充值接口返回原始允许方式和服务端最小请求数量；充值订单没有通过假成功数据冒充到账。

本轮使用 Chrome 自动化浏览器在三个独立 `.localhost` 隔离账户上完成端到端 QA，所有账户只连接 PostgreSQL 临时测试库和本地合成上游；生产端口 3000/3100 未被这些写入操作使用。聊天覆盖流式 Markdown、复制、重命名、刷新恢复、QA_FAIL 错误保留和 QA_SLOW 停止；画室覆盖服务分组、无效数量、价格预估、两张图片批次、作品预览、单张/批量下载、失败筛选和删除确认；模型/密钥覆盖倍率报价、标签/接口能力搜索、空结果、图片 CTA、分页、额度校验、并发 Reveal 和创建表单；钱包/账户覆盖兑换、重放拒绝、订单空态/搜索、套餐购买与限购、扣费偏好持久化、资料保存、撤销其他会话、登出和受保护页面回跳。浏览器控制台无报错。截图保存在 `.local-tests/factory-consumer/browser-qa/`，例如 `creation-chat-fail.png`、`creation-image-preview.png`、`access-model-details.png`、`access-key-edited.png`、`account-wallet-redeemed.png`、`account-plan-purchased.png`。生产产物已检索，不含测试账户、合成 API Key 或模拟上游回答。

## 本轮真实渠道复验（2026-10-19）

本轮使用 PostgreSQL 临时副本 `factory_channels_qa_152779d69c` 和真实渠道配置，未改动原 `new-api` 数据库、渠道状态或管理后台。通过 Chrome 在 `channels.localhost:3116` 使用隔离测试账户完成了以下最小请求：

- `default / gpt-6-luna` 流式聊天成功返回中文回答，服务端记录 1 quota（输入 26、输出 22 tokens）；随后 `default / gpt-6.1-sol` 流式聊天同样成功，记录 10 quota（输入 16、输出 10 tokens）。
- `test / gpt-image-2` 单张图片生成成功。提交前服务器报价 **US$0.875**，任务约 24 秒完成，作品库预览、详情和签名下载链接均成功；服务端最终记录 **437,500 quota = US$0.875**，与报价一致。
- 隔离账户从初始 5,000,000 quota 扣除 437,511 quota（US$0.875022）（两次聊天与一次生图），页面余额和 `/api/user/self` 一致。用量页显示三笔请求及其分组、模型和最终费用。
- 临时 API Key 创建、列表掩码、`/v1/models` 返回 8 个模型、禁用后访问返回 401、随后删除临时 Key 均成功。一次带本机 IP 白名单的试验得到 403 且未扣费；此结果发生于访问限制检查，不能作为供应商失败的证据。不设白名单的隔离 Key 完成了上述模型目录和启停契约验证；未将其作为 API Key 发起真实模型调用成功的证明。
- 选择没有生图模型的 `default` 分组时，页面此前只显示空模型选择框；本轮已修复为明确的无模型提示，并只展示通过 `/api/user/models` 实际确认可用的 `test · 1.75×` 切换建议。画室异步批次完成、部分失败或失败时现在显示对应状态，且只读刷新余额、用量和作品缓存；相同终态不会重复提交或重复刷新。

上述真实请求产生的供应商费用取决于已配置渠道；本轮仅使用隔离账户和最小提示，未执行支付、充值、兑换码、OAuth、邮件或账户安全变更。服务端日志仍保留公共 token 字段，前端对图片请求改用图片数量字段，缺少可靠数量时显示“—”；固定图片计费的真实金额以服务端 quota 和 billing metadata 为准，Usage 页面不会在前端重新计算账单。损坏、数组或 null 的历史附加数据安全降级，避免消费页崩溃。

本轮结束后已停止专用端口 3006/3116，删除临时数据库及含配置的重复备份、日志、凭据，原3000/3100仍返回200。截图保留在 `.local-tests/factory-consumer/browser-qa/channel-chat-real.png` 和 `channel-image-preview-real.png`。未改动旧前端或核心计费；组件扩展复用独立 consumer 的 ServicePicker、EmptyState 和 Button。

## 本轮使用体验优化（2026-10-19）

根据使用反馈，本轮把高频流程改为少跳转、少确认：

- 画室与作品合并为同一工作空间：创作表单与作品流在同页展示，任务提交后立即出现，进度、预览、下载、筛选和失败详情均在当前页完成；`/library` 仍保留兼容入口。表单只在当前页面保留，离开路由后的草稿恢复尚未实现，见下方六角色评审。
- 聊天记忆服务分组与模型，按账户和场景隔离；首次进入会从当前账户实际可用模型中自动选择。画室目前只记忆服务分组，没有接入模型偏好恢复；先前将聊天与画室一起描述为已完成模型记忆不准确，本轮浏览器评审已纠正。
- 服务分组和模型选择改为可搜索、可键盘操作的选择器；过渡动画支持 `prefers-reduced-motion`。
- API Key 列表显示已用、剩余、总额度和剩余额度进度条；无限额度、过期和额度耗尽有明确状态。列表支持页码、跳页和每页条数。
- 充值和套餐支付方式改为平铺卡片，快捷金额与自定义金额自动重新报价；金额或方式变化时旧报价立即失效，报价完成前不能确认下单。订单支持搜索回到第一页、页码和每页条数。
- 用量页增加时间、服务分组、模型、模型匹配规则、API Key、请求 ID、记录类型筛选；请求详情展示服务端公开的计价模式、缓存 token、计费倍率、计价档位、用量事实和计费 token 拆分，不在前端重算金额。

本轮统一体验环境使用本地隔离 SQLite 和模拟上游，未连接真实供应商或支付。原 3000/3100 环境未改动；本轮 3007/3117 及测试数据在结束后清理。

## 安全依据和校验

依据 OWASP ASVS **5.0.0**：

- **10.1.2**：同浏览器事务绑定。每次 consumer OAuth 使用独立 `__Host-` HttpOnly/Secure/SameSite=Strict Cookie；验证后在响应头提交前清除。
- **10.2.1**：授权码流程 CSRF 防护。一次性 state、PKCE S256、固定回调、严格 Origin/Referer；拒绝任意回调目标。
- **10.2.2**：多提供商 mix-up 防护。provider 专属固定回调与服务端 flow 共同绑定。

官方版本：[ASVS 5.0.0 OAuth/OIDC](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x19-V10-OAuth-and-OIDC.md)。同时查阅 [Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)、[MFA](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)、[Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)、[OAuth2](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html)。

回归覆盖：MFA challenge 不能直接升级登录；只内存保存凭据；单飞刷新；退出后旧刷新不复活；跨账户/跨标签竞态；写入、proof 和 OAuth callback 不重放；proof 的 scope/context 服务器校验；错误来源/浏览器/cookie/provider、过期、消费重放；真实 HTTP token 交换参数；恢复邮件 SMTP 链接；退出失败不伪装成功。浏览器联调还发现并修复了标签可见性/HMR触发的过量刷新：有效令牌与同sid消息不刷新，429后停止自动重试；恢复失败仍允许访问公开首页和登录页。

上述验证针对新增与受影响控制，不是对整个历史后端的 ASVS 合规认证。
