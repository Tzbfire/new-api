# New API Consumer — 产品与实施方案

## 目标与边界

在 New API 之上新建独立消费级用户应用。独立源码、依赖、路由、组件、样式、测试和静态产物；没有 `web/src` 导入，不替换旧控制台。默认同域名根路径，`/_factory/` 为独立资源命名空间，`/api/` 和 `/pg/` 继续由原 Go 服务提供。旧管理界面仅增加新版启用开关和返回新版入口；已有 `web/default/`、`web/simple/` 未跟踪文件属于原工作区，不纳入本项目。

已检查旧站 CopyButton、ConfirmDialog、ErrorState、Pricing 实现及调用。用户明确要求独立组件系统，因此不导入、复制或改写这些组件；新组件在本项目内统一复用。独立应用不应跟随旧站内部状态管理和样式变动。

## 源码和数据研究

- `router/api-router.go`、`router/relay-router.go` 是接口边界。Go 的 `web/dist` embed 和 `router/web-router.go` 保持原样。
- 认证是内存 access JWT + HttpOnly refresh cookie，不是旧 `New-Api-User` 协议。冷启动经 `/api/user/auth/refresh` 恢复，管理和 playground 请求带 Bearer。敏感操作使用服务器签发的一次性 proof；不得重放。
- 分组同时约束可用模型和实际计费倍率。`/api/user/self/groups`、`/api/user/models?group=` 和 `/api/pricing` 是权威来源。UI 推荐用户当前可用默认组，不擅自授予模型权限或声称某组服务更快。
- `/api/pricing` 暴露旧倍率和动态表达式。前端不实现第二套表达式引擎；只读兼容扩展负责给出服务端价格展示/情景试算。动态价格明确条件，最终消费以服务端记录为准。
- 聊天复用 `/pg/chat/completions`，流式消费 OpenAI SSE；现有后端没有聊天历史表或同步 API，本机历史独立按用户隔离，明确保存范围。
- 画室使用 `/pg/image-studio/config`、`estimate`、`generations`、`edits`，以及 `/api/image-studio/batches`、`library/tasks`、下载票据。`count` 是批任务数量，提交成功不等于作品生成完成。
- API Key 使用 `/api/token`；钱包/充值使用 `/api/user/topup` 等；订阅使用 `/api/subscription`；统计使用 `/api/log/self` 和汇总接口。支付金额和支付状态以服务端为准。
- 只读检查本地 SQLite：`new-api.db` 无表；`one-api.db` 为旧版 25 表，包含 users/tokens/logs/top_ups/subscription_plans/user_subscriptions/tasks，缺少当前画室表。未读取用户行、密钥或账户余额。不能将旧本地库作为现版本集成验证环境。
- 现有支付渠道的回跳地址并不全部支持自定义；充值订单和订阅记录应区分，不能把订阅记录伪装为待支付订单。

## 视觉与交互

站点品牌来自后台的既有公开站点配置，可通过私有构建环境覆盖；公共默认名称为 New API，使用通用图标，保留 New API / QuantumNous 归属。部署的品牌、域名和默认语言不固化在公共源码。模型聚合、服务分组与实际价格、统一 API、密钥、调用记录和充值是首页与导航的主要信息，聊天和画室提供直接使用模型的入口。暖白画布、墨色正文、珊瑚色主动作；淡紫和鼠尾草绿作为辅助色。克制边框、宽松留白、圆角卡片、统一 8px 间距尺度。深色使用独立语义变量，跟随系统或手动选择。语言默认跟随浏览器并回退英文，支持部署默认值和持久化的用户选择；中文标题与正文使用系统中文字体，英文标题使用本地字体包。动效仅用于反馈与进入，尊重 reduced-motion。

组件：Button / Field / Input / Select / Textarea / Card / Badge / Modal / ConfirmDialog / CopyButton / PageHeader / LoadingState / ErrorState / EmptyState。弹层使用 Base UI 管理焦点、Esc 和键盘；表单保留原生 label/校验语义。所有有副作用动作显示 pending，失败保留输入，不自动重复付款、生图或消费请求。

## 技术架构

React 19 + TypeScript + Rsbuild，TanStack Router / Query，Base UI，i18next，Lucide，Bun。路由懒加载，服务端状态独立缓存，认证状态仅内存。请求层统一处理业务失败、网络失败和取消，refresh 合并并发请求。只持久化主题、语言、服务方案及明确标识的本机聊天记录；不存储 access token、密码、OTP、proof、API Key。

`src/features` 为业务边界；`src/lib` 仅放 API、格式化、会话、服务分组与契约；`src/components` 提供独立设计系统。测试数据只存在测试服务器/测试目录，生产构建无演示账户或伪造余额。金额展示仅单位换算，报价与扣费由后端完成。

## 分阶段执行与验收

1. **研究与方案**：确认接口、认证、数据库实体、价格及支付限制，记录本文件。
2. **独立基础**：创建项目、语义主题、公共组件、路由、API/会话、七语言体系、同源部署配置。
3. **创作闭环**：聊天流/停止/本机历史，画室预估/提交/后台进度/作品下载与管理。
4. **商业与账户**：方案模型价格、API Key、用量、钱包/支付/套餐/订单、个人安全。
5. **验证与优化**：类型、lint、国际化、生产构建；后端兼容扩展回归；浏览器验证桌面/移动/深色、核心交互和失败路径。真实供应商生成、真实支付及生产部署单独记录，不用模拟结果代替。

## 上游同步与部署

价格试算和充值最小数量元数据为兼容只读扩展。OAuth 固定 consumer 回调枚举、PKCE 与浏览器绑定、找回密码回调保持原有保证。根路径发布仍保留 `/app/oauth/*` 和 `/app/reset`，避免升级前流程失效。没有新增数据库模型或迁移，不修改结算路径。

Go 在返回 HTML 前按页面路径、全站 `frontend_setting.enabled` 与非敏感 `factory_frontend` 界面偏好选择新旧界面；未部署新版资源或全站关闭时回到旧版等价页面。用户套餐 `/plans` 的旧版等价入口为 `/wallet`，其中提供套餐购买；`/subscriptions` 为管理员套餐管理，始终交原前端。管理路由和无新版等价功能的页面继续交原前端，不覆盖用户偏好。`router/frontend.go` 中的用户页面别名表在新版启用且可用时将旧书签转到新版等价页；共享偏好脚本向旧版根路由提供同一份选择规则，旧版 SPA 内部导航也不会绕过网关。登录地址仅转换经过校验的站内返回目标，管理登录目标及既有认证回调继续按原入口处理。两套 hash 资源分开，支持历史静态目录，部署细节见 README 与 deploy/nginx.conf。首次更新 Go 入口能力后，consumer 静态产物可独立发布、原子切换或回滚。认证密钥、Cookie、公开域名和原数据库在仅切换界面时保持原配置。

## 安全验证基线

遵循 OWASP ASVS 5.0 与 Authentication / Session Management / MFA / CSRF / Forgot Password Cheat Sheets 的适用要求；完整引用、运行命令和尚未验证的实网边界在交付验证记录中列明。浏览器验证不宣称对整个既有后端完成 ASVS 合规认证。

### 路由与认证边界

`lib/route-guards.ts` 的 `beforeLoad` 在进入私有路由前等待认证，确认前不挂载工作台/Catalog 或执行子 loader。login/register 使用访客守卫；OAuth 和密码恢复回调保持独立。模型广场通过共享 status 查询读取 HeaderNavModules 策略。`components/route-guard.tsx` 复用现有加载/错误控件，在已挂载页面上立即响应身份失效，身份和 SID 变化重新校验路由并清理私有查询。

`lib/api.ts` 的认证协调器让公开启动、守卫和请求共用 refresh 单飞与浏览器锁。状态区分本地未确认匿名、服务端确认匿名和可重试恢复错误；可读 hint 不是身份凭据，保护页无 hint 也会向后端确认 HttpOnly 会话。终态 401 撤下身份，网络/5xx/429 不伪装退出；普通 403 不当作登出。GET 最多刷新重试一次，写请求与安全 proof 不重放。后端认证/授权中间件仍是权限和数据隔离的最终执行者，前端版本偏好与路由守卫不能授予 API 权限。

### 公共浏览与个人工作台

首页与 `/explore` 使用 consumer 自己的 `PublicHeader`/`PublicFooter`，模型页使用无侧栏的 `PublicLayout`。公开导航专注模型、聊天与画室入口；账户身份只决定右上角登录/进入工作台操作。API 密钥、余额、账单、订单和资料安全保留在受保护的 AppShell；工作台侧栏、快速指南及服务选择器的价格入口进入 `/model-pricing`，保持同一侧栏与收起状态。两条模型路由复用同一个懒加载 ExplorePage、CatalogProvider 和价格组件，不维护第二套模型或计费逻辑。子页面加载反馈在工作台内容区域内呈现。

`/model-pricing` 同时经过认证守卫与既有 HeaderNavModules 模型模块策略；分组/模型参数保留在登录返回和使用入口中。网关识别该路由及 `/app/model-pricing` 兼容入口；旧版偏好、关闭新版或资源不可用时回到 `/pricing` 并保留查询条件。公开 `/pricing` 书签仍映射 `/explore`，管理模型路由 `/models` 不变。已登录时两处目录均请求该用户有权限的分组/模型，权限与计费继续由后端执行。

Preferences 从 AppShell 提取为共享组件，首页与目录无需为了主题控件导入整个工作台。PublicHeader 组合已有 Brand、FrontendEntry、AnnouncementButton、Preferences、Button/Modal；手机菜单保持相同产品导航，Escape 关闭并返回焦点。旧 web 的 PublicLayout 仅作为结构参考，未被 consumer 导入。

### 围绕服务分组选择模型

模型目录使用紧凑双列卡片；手机变为单列。卡片只展示后台提供的名称、简介、接口类型、当前分组可用性、实际单价和两项性能摘要。标题下直接平铺所有服务分组选项，显示名称、倍率、选中态与当前说明；手机自动换行，无下拉或展开步骤。目录与详情复用 ServiceGroupOptions，组合已有 Button 和语义 fieldset；SearchSelect 的弹出菜单行为不适合这里的常显比较需求。搜索可匹配后台简介和标签，用户可以发现当前分组之外的模型，再在详情中直接点击可用分组。不支持模型的组保留可见并标注禁用状态。没有描述、独立单价或性能样本时明确保留缺失状态，不按模型名称推测上下文长度或其他能力。

详情复用现有 Modal，分为概览、价格与分组、性能趋势；顶部保留分组选择，底部固定聊天/画室/API 密钥入口，切换分组不关闭模型。切换详情区段仅重置内部滚动。所有开始使用的链接携带模型和分组，通过现有登录回跳延续到聊天、画室或密钥接入示例。

`ModelPriceSummary` 从现有 ModelPriceList 提取，卡片、概览、跨组比较共用；`ModelPrice` 继续负责按用量试算。金额、单价、倍率与示例总价全部来自 `/api/pricing/quote`，不在前端重算账单。不同计费单位分别标注。登录用户逐组通过 `/api/user/models?group=` 确认访问范围后展示对应价格和使用动作。Catalog 将公共目录元信息与分组权限的加载状态分开，切组时保留页面结构，避免整页闪烁。

`performance.ts` 为同一身份和模型共享一次 24 小时性能查询，所有摘要与分组比较只取确切 group，不能回退全模型平均值。`PerformanceTrend` 是该模块的观察点图，按实际时间定位，支持点击/触摸和方向键；缺失时段不补点、不连成持续服务状态。现有消费趋势组件的输入是按日消费汇总，无法表达这四项不同单位的指标及缺失观察，因此新增该业务组件；普通控件继续复用 consumer 的 Button、SearchSelect、Pagination、Modal 和价格组件，未导入旧 web UI 或新增图表依赖。

性能接口只增加现有统计器的请求数、成功数、TTFT 样本数、TPS 是否有观测标志；没有数据库或统计公式变化。成功率是被统计请求的完成结果，非按时间在线率；总耗时包含失败和重试，TTFT 只覆盖记录首响应的流式请求且不保证等于首个可见字符；TPS 按累计 token / 累计生成时长计算。`auto` 的实际表现归入最终承接请求的具体分组。界面说明查询窗口、最新样本、指标口径以及数据库与当前进程热数据的覆盖限制。
